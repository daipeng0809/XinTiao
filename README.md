# 信息调试助手（XinTiao）

一款基于 .NET 10 + Avalonia 的跨平台串口 / 网络调试工具，支持 Windows x64 与银河麒麟 V10（Linux arm64），
采用 NativeAOT 发布，目标机器无需安装 .NET 运行时。

当前版本：**V1.6.0**

---

## 一、功能清单

### 1. 连接方式（左侧页签）

| 方式 | 说明 |
| --- | --- |
| 串口 | 自动枚举本机串口，可设置波特率、校验位、数据位、停止位 |
| TCP 客户端 | 指定本地 IP / 端口（本地端口 0 表示系统自动分配）主动连接对端 |
| TCP 服务端 | 监听本地端口，允许多个客户端接入；收到多个客户端的数据汇总显示，发送时广播给所有客户端；发送文件协议传输可选择目标客户端单播 |
| UDP | 绑定本地端口收发，运行中可随时修改对端 IP / 端口，修改立即生效 |

- 同一时刻只允许一个通道处于打开状态，打开后其余页签自动锁定，避免多通道混收。
- 右上角状态徽标显示当前连接状态（未连接 / 已打开 / 监听中 / 正在断开），并显示串口名、对端地址或客户端数量。

### 2. 接收区

- 文本显示 / HEX 显示一键切换。
- 可选择是否在每条数据前显示时间戳（精确到毫秒）。
- **显示发送**：开启后，自己发送的数据也以“发送=>”前缀回显在接收框（默认关闭）。
- **保存数据**：开启后，接收框显示的内容会保存到程序目录 `Data` 文件夹，文件名按日期时间命名（如 `2026-11-19_13-05-42.txt`）；目录不存在时自动创建，程序目录不可写时回退到用户目录。
- 接收内容鼠标可选中复制，接收区自动滚动到最新内容。
- 底部状态栏实时统计累计接收、发送的字节数，可一键清空接收区 / 发送区。

### 3. 发送区

发送区标题右侧是 **单条数据 / 多行数据** 两个页签（紧贴标题，不单独占一行），公共选项位于发送区右上角。

公共选项：

- **加回车换行**：勾选后，发送内容末尾自动追加 CR LF（HEX 显示为 `0D 0A`），文本 / HEX 发送均生效。
- **文本发送 / HEX 发送**：单条数据的发送方式（HEX 输入支持 `AA BB 11 22` 这种带空格的写法，并会对非法字符、奇数长度给出提示）；切到多行数据页时该开关会置灰，由每行自己的 HEX 勾选决定。

单条数据页：

- 一个多行输入框，输入内容后点击“发送”。
- 可按指定间隔（毫秒）定时发送，再次点击“停止发送”结束。
- **发送文件**：点击后弹出系统文件选择框，选中文件后再弹出“发送选项”窗口（见下节）。

发送文件（V1.4.0 新增，V1.5.0 增加协议传输）：

- **传输方式**：
  - **裸流发送**：无协议，把文件按分块大小直接拆成字节连续发送，没有握手、校验与重传；可设置分块间隔防止下位机缓冲区溢出。
  - **协议传输**：每帧带帧序号与 CRC16，接收方逐帧回 ACK，超时或 NAK 自动重传，可靠传输；对端需按下方帧格式实现应答。TCP 服务端下可选择目标客户端，只把数据单播给它、并且只认它的 ACK，多客户端时也能可靠传文件。
- 裸流选项：发送方式（**原始二进制** / **HEX 文本**）、分块大小（1~65536 字节）、分块间隔（0~60000 毫秒）、HEX 文本每块末尾是否追加 CR LF。
- 协议选项：分块大小即每帧载荷（1~65535 字节）、分块间隔、ACK 超时（50~60000 毫秒）、最大重传次数（0~20 次）；TCP 服务端还会显示“目标客户端”（可刷新列表）；协议传输固定按原始二进制发送，HEX 文本与追加换行不可用。
- 点击“发送”按块把文件写入当前串口 / TCP / UDP 连接，进度条实时刷新；协议模式按“已确认”字节统计进度，并显示当前帧号与重传次数。
- 连接断开、服务端没有客户端、或协议模式超过最大重传次数仍未收到 ACK 时立即报错停止；发送选项会记忆，下次打开自动恢复。
- 全部发送完成后，若开启“显示发送”，接收区会回显一条“发送文件=>”记录。

协议帧格式（V1.5.0）：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 帧头 | 2 | 固定 `AA 55` |
| 类型 | 1 | `01` 数据帧 / `02` ACK / `03` NAK（请求重传） |
| 帧序号 | 2 | 小端，从 0 开始逐帧加 1，回绕后继续 |
| 载荷长度 | 2 | 小端，0~65535 |
| 载荷 | n | 文件内容（原始字节） |
| CRC16 | 2 | 小端，CRC-16/MODBUS（多项式 0xA001、初值 0xFFFF、结果不异或），覆盖“类型 ~ 载荷” |

- ACK 帧：类型 `02`、序号与对应数据帧一致、载荷长度为 0；NAK 帧同理，表示要求重发该序号。
- 发送端只有收到同序号 ACK 才发下一帧；超时未收到或收到同序号 NAK 时重发，超过“最大重传”次数即中止并提示。
- 协议传输期间收到的应答帧不会显示在接收区，传输结束后恢复正常接收显示。
- **TCP 服务端的目标客户端**（V1.6.0）：协议数据只发给所选客户端，并且只把该客户端返回的数据当作 ACK；目标客户端断开时立即停止并提示，其余客户端的数据仍照常显示。裸流发送不受影响，仍广播给所有客户端。

多行数据页：

- 每一行是独立的一条待发数据，每行都是单行高度（输入框、HEX、间隔、定时发送、发送、删除在同一行），尽量节省空间；
- 每行可单独设置：发送内容、是否 HEX、定时发送间隔（毫秒）。
- 每行都有“发送”“定时发送 / 停止发送”“删除”按钮，多行之间互不影响，可同时运行多个定时任务。
- 数量可随时增减：“增加一行”“删除末行”，或直接删除指定行（至少保留一行）。
- 行数较多时可上下滚动查看。

### 4. 数据校验（底部状态栏“校验计算”）

- 校验类型：**CheckSum 累加和 / BCC 异或校验 / CRC 循环冗余校验 / LRC 纵向冗余校验**。
- 输入支持 HEX / 字符两种模式：HEX 允许空格、逗号、分号分隔以及 `0x` 前缀；字符按 UTF-8 编码参与计算。
- 具体校验方式随类型联动：
  - CheckSum：8 / 16 位累加和、累加和取反、累加和补码；
  - BCC：8 位异或、异或取反；
  - CRC：CRC-8、CRC-8/MAXIM、CRC-16/MODBUS、CRC-16/IBM（ARC）、CRC-16/CCITT-FALSE、CRC-16/XMODEM、CRC-16/X25、CRC-16/DNP、CRC-32；
  - LRC：LRC-8（Modbus ASCII）、LRC-16。
- 结果同时以 HEX / DEC / OCT / BIN 四种进制显示，支持单项复制与“复制全部”；多字节结果可选“低字节在前（小端）”，方便直接粘贴到指令末尾。
- 输入实时计算；非法 HEX 会定位到具体字符并提示原因。
- **导入**（V1.4.0 新增）：一键把主窗口“单条数据”发送框中的内容与当前“文本 / HEX”状态导入校验窗口，省去重复输入。
- **发送到主窗口**（V1.6.0 新增）：把当前输入内容与 HEX / 字符模式填入主窗口发送框，校验后可直接发送。
- 校验窗口以主窗口为 Owner 居中打开，重复点击只激活已打开的窗口。

### 5. Modbus 工具（底部状态栏“Modbus”，V1.6.0 新增）

- 支持 **Modbus RTU**（从站地址 + PDU + CRC16）与 **Modbus TCP**（MBAP + PDU）两种模式。
- 功能码：01 读线圈、02 读离散输入、03 读保持寄存器、04 读输入寄存器、05 写单个线圈、06 写单个寄存器、0F 写多个线圈、10 写多个寄存器。
- 参数随功能码联动：读类显示“数量”；05 / 06 显示“写入值”；0F / 10 显示“数量”与“多写数据”（HEX，按数量自动校验字节数）；TCP 模式额外显示事务号。
- 生成结果实时刷新，自动带 CRC16 或 MBAP；支持“复制报文”与“发送到主窗口”（填入单条发送框并切换为 HEX 发送）。
- 报文解析：粘贴 RTU / TCP 响应报文，自动校验 CRC / MBAP 长度与协议标识，解析功能码、字节数、寄存器值、线圈状态、写响应与异常码（异常码附中文含义）。

### 6. 其他

- **多配色方案**：底部状态栏右侧下拉框可切换 6 套配色：浅色、深色、海蓝、森林、紫夜、多彩；选择后立即生效并自动保存，下次启动自动恢复。
- **关于软件**：底部状态栏“关于”打开，显示程序图标、版本、作者（大鹏鹏）、邮箱（daipeng0809@hotmail.com），以及版权、免责、数据隐私与第三方组件声明，可一键复制邮箱。
- 左上角名称后显示当前程序版本号（从程序集版本自动读取）。
- 所有参数与输入内容实时保存（停顿 500ms 自动落盘），下次启动自动恢复：串口参数、TCP / UDP 参数、显示方式、发送方式、定时间隔、加回车换行、**单条发送内容**、多行发送内容与每行设置、发送文件的传输方式 / 分块大小 / 间隔 / ACK 超时 / 重传次数、当前所在页签、配色方案等。
- 配置文件优先写入程序目录 `Config/AppConfig.json`；安装目录只读（如 `/opt`、`Program Files`）时自动回退到用户目录：
  - Windows：`%APPDATA%\XinTiao\AppConfig.json`
  - Linux：`~/.config/XinTiao/AppConfig.json`

## 三、使用说明

1. 左侧选择连接方式并填写参数，点击“打开串口 / 连接 / 开始监听 / 打开”。
2. 右上角状态变为绿色并显示连接信息，说明连接成功。
3. 在发送区选择“单条数据”或“多行数据”，输入内容后发送；需要协议结尾带回车的场景，打开“加回车换行”。
4. 需要发送文件时，点击“发送文件”选择文件，在“发送选项”窗口确认发送方式与分块参数后点击“发送”，发送中可点“停止”中断；TCP 服务端使用协议传输时，先选择“目标客户端”。
5. 接收区可按文本 / HEX 查看数据，勾选“显示时间”可看到每条数据的接收时刻。
6. 需要计算校验值时，点击底部状态栏右侧的“校验计算”：选择校验类型与具体校验方式，输入 HEX 或字符内容，下方会实时显示 HEX / DEC / OCT / BIN 结果，可单项或全部复制；点击“导入”可直接带入主窗口发送框的内容与文本 / HEX 状态，点击“发送到主窗口”可把当前输入内容带回发送框。
7. 需要构造 Modbus 报文时，点击“Modbus”：选择 RTU / TCP、从站地址与功能码，填写起始地址、数量或写入值，生成结果会实时显示；可复制，或点“发送到主窗口”直接填入发送框。
8. 需要查看软件信息时，点击底部状态栏“关于”：可看到程序图标、版本、作者、邮箱与相关声明。
9. 关闭窗口时会自动关闭并释放当前通道。

小提示：

- HEX 发送要求去掉空格后字符数为偶数，且只能是 `0-9 / A-F / a-f`。
- 校验窗口的 HEX 输入同样支持空格 / 逗号 / 分号分隔与 `0x` 前缀；字符输入按 UTF-8 编码参与计算。
- CRC 等多字节结果默认按大端显示，协议要求低字节在前时可勾选“低字节在前（小端）”。
- TCP 服务端尚未有客户端接入时发送会给出提示，先让客户端连上再发送。
- 发送文件：原始二进制模式按字节原样发送；HEX 文本模式每个字节占两位十六进制，分块大小与间隔可按对端接收能力调整（波特率较低时建议减小分块、加大间隔）。
- 协议传输需要应答端按上面的帧格式回 ACK；对端没有实现该协议时请使用裸流发送，HEX 文本模式仅裸流可用。
- TCP 服务端接入多个客户端时，协议传输请在“目标客户端”中选择接收方；目标客户端断开后传输会立即停止，其余客户端的数据只显示、不参与 ACK。
- Modbus 工具：RTU 帧自动追加 CRC16（低字节在前），TCP 帧自动带 MBAP；解析时左侧协议要与报文一致（RTU 报文用 TCP 模式解析会提示长度错误）。
- 定时发送启动前会校验内容与连接：HEX 格式非法、服务端还没有客户端接入时不允许启动；运行中内容变成非法 HEX（或被清空）时，该行 / 单条的定时会自动停止，避免“看着在发、实际没发”。
- 多行页的定时发送在连接断开或关闭通道时自动停止。

## 四、Linux（银河麒麟）安装

程序发布目录中已包含 `install.sh` 与 `XinTiao.desktop` 模板。

```bash
# 1. 进入程序所在目录（把程序、Assets 目录、install.sh 放在一起）
cd /opt/xintiao

# 2. 赋予执行权限（程序与脚本）
chmod +x 信息调试助手 install.sh

# 3. 生成桌面启动文件并安装到应用菜单（当前用户）
bash install.sh

# 或者：安装给所有用户
sudo bash install.sh

# 也可以手动指定程序路径
bash install.sh /opt/xintiao/信息调试助手
```

脚本会做这些事：

- 自动识别同目录下的可执行程序（也可通过第一个参数指定）；
- 自动识别图标（优先 `Assets/wk.png`，其次 `Assets/wk-256x256.ico`）；
- 在程序目录生成 `XinTiao.desktop`，`Exec` / `Icon` / `Path` 全部为程序当前真实绝对路径；
- 在程序目录创建 `Data` 目录并授予写入权限（用于保存接收数据）；
- 复制到 `~/.local/share/applications`（root 用户为 `/usr/share/applications`）并刷新菜单缓存。

安装完成后，在应用菜单中搜索“信息调试助手”或“XinTiao”即可启动。

> 如果脚本是从 Windows 复制到 Linux 的，出现 `$'\r': command not found` 之类错误，先执行：
> `sed -i 's/\r$//' install.sh` 再运行。

## 五、构建与发布

```bash
# 本地调试运行
dotnet run

# Windows x64 发布（NativeAOT）
dotnet publish -c Release -r win-x64 -p:PublishAot=true

# 银河麒麟 V10（linux-arm64 / linux-x64）发布，需在目标架构机器上执行
# 依赖：sudo apt install clang lld zlib1g-dev
dotnet publish -c Release -r linux-arm64 -p:PublishAot=true
```

发布目录会同时带上 `Config/`、`Assets/`、`install.sh`、`XinTiao.desktop` 与本说明文件。
